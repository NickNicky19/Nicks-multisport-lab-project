## Intended outcome

Build an NBA-first, multisport player-outcome research website and paper-ticket
system. Forecast full outcome distributions, evaluate them chronologically, and
use supported current contracts and actual payout terms for paper value research.
The quality goal is rigorous, reproducible research and engineering. No achieved
hit rate, profit, sportsbook advantage or validated live model is claimed.

The paper builder supports 2–6 legs. Six legs are preferred when the complete
ticket qualifies; fewer legs and `NO_ACTION` remain valid. Keep `OVER_ONLY`,
`UNDER_ONLY` and `MIXED` as separately evaluated policies. Report complete ticket
results and settlement, not only individual leg hit rates.

Both Props and Paper Builder require single-sport, selected-multiple-sport and
all-supported-sport scopes. Define that contract in the initial NBA interface;
available choices follow actual sport coverage. Keep the displayed opportunities
and ticket candidate universe within the chosen scope.

## Full category scope

NBA includes all 13 requested categories:

| Code | Category |
| --- | --- |
| PTS | Points |
| PRA | Points + rebounds + assists |
| REB | Rebounds |
| 3PM | Three-point field goals made |
| AST | Assists |
| RA | Rebounds + assists |
| PR | Points + rebounds |
| TOV | Turnovers |
| TD | Triple-double |
| DD | Double-double |
| BLK | Blocks |
| STL | Steals |
| BLK+STL | Blocks + steals |

PA (points + assists) is an optional additional category. Shared participation,
minutes, role and game-environment inputs support coherent joint outcomes;
combination statistics and DD/TD indicators are derived consistently. Each
category still needs its own coverage and evaluation evidence.

The first controlled REB improvement experiment is one research comparison within
the full NBA scope. It does not limit the project to rebounds or delay recording
usable evidence for the other categories.

Each later sport has the same comprehensive-category goal. Inventory its actual
markets and underlying statistics before choosing a bounded first improvement.
Coverage and validation are earned per category; unsupported categories stay
explicitly visible in the capability register.

## Operating constraints

Use no new paid services, subscriptions, trials, signups or API keys under the
initial scope. Assess permitted public data, existing authorized access and
retained user-provided files. ESPN DraftKings-labelled props and Sleeper are
adapter candidates; their availability, prices, definitions and permitted use
must be established for each implemented sport and contract family.

Keep raw and large historical datasets outside Git. Separate historical data,
forecasts, quote observations, grading and published website assets. A static
website can display validated generated assets; it does not itself establish a
working collection or model pipeline.

Use one Codex integration owner initially, with coordinated agents on bounded
work packages and a common data/cutoff/evaluation contract. Do not create
competing writers, duplicate workbooks or repositories, or a second scheduler.
Routine authorized implementation should continue without repeated confirmation;
an unresolved requirement should be recorded precisely while unaffected work
continues.
